# Theming

Every colour on the page is a CSS variable generated by `scripts/theme.mjs` from `answers.theme`.
The page itself has no hard-coded colours.

## Choices to offer
| Option | What to ask | Notes |
|---|---|---|
| **Preset** | Pick one: Slate, Ocean, Forest, Sunset, Berry, Mono, High contrast | Safe default: Slate |
| **Company brand** | "What are your brand's main colour and one or two accents? Hex codes are best." | Never guess a company's colours. If they only give a name, ask them to check their brand guidelines or website. If you suggest values, mark them as suggestions and get a yes |
| **Custom** | "A main colour, plus optionally up to three accents and a header colour" | Any CSS hex |

Only `primary` is required. If something is missing, theme.mjs derives it: the accents are hue-shifted
from primary, and the header is a deep shade of primary.

`theme.colors` keys: `primary, accent1, accent2, accent3, head1, head2` (header gradient from head2 to head1).
To override the neutrals, use `light_page, light_surface, light_ink, dark_surface…` (rarely needed).

## Readability (automatic)
theme.mjs checks WCAG contrast for both light and dark mode and **adjusts any colour that fails**:
- body text 7:1, secondary and hint text 4.5:1, link and key text 4.5:1
- big numbers, bars and accents 3:1 (they're large and bold)
- button and header text: picks white or near-black, whichever reads better, and warns below 4.5:1

The build prints every adjustment ("light: primary #ffcc00 → #b28f00 …"). Tell the user in plain
words, e.g. "your yellow was too pale to read on white, so numbers use a deeper gold. The header
keeps the original yellow." For a quick report: `node scripts/theme.mjs <project>/answers.json`.

## Logo
- `monogram` (default): initials in a rounded square in the primary colour
- `url`: an **https** image (PNG/SVG). It's shown on a white tile unless `"boxed": false`
- `svg`: pasted `<svg>…</svg>`. Scripts and event handlers are stripped
- `none`

## Mode
`auto` follows the device and adds a ◐ toggle (remembered per browser). `light` or `dark` fixes it.
Always preview both when auto: `preview.mjs <project>` and `preview.mjs <project> --dark`.
